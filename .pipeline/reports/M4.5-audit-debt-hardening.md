# M4.5 审计债务硬化报告

- 时间：2026-05-07T23:37:52+08:00
- 状态：完成
- 来源审计：`.pipeline/audits/audit-002.md`
- 范围：M2-M4 实现的补充硬化，不启动 M5 响应式重构

## 修复摘要

本轮针对 Subagent 审计后的 M4.5 门禁完成五类修复：

1. 乐观发送消息生命周期收敛：排队发送会带 `clientMutationId` 与 `deliveryState`，队列清空会移除仍 pending 的乐观消息，provider final 到达后会确认并替换匹配的乐观 user message，避免刷新后重复或吞消息。
2. 错误事件统一安全化：后端非 HTTP 的 stderr/protocol/provider/live refresh 错误进入 `AppError` 安全模型，错误摘要和技术细节均脱敏，避免路径、token、secret 泄漏到前端。
3. 重试目标显式化：发送失败卡片记录 `sessionId/text/tokens`，重试只重放对应发送；非发送错误不再伪装成发送重试。
4. 错误卡去重与冷却：SSE 断连按 `dedupeKey` 合并为一张卡；429 本地与后端错误都携带 cooldown，按钮在冷却期间禁用并显示倒计时。
5. 旧状态污染收窄：取消/过期 detail 请求和 refresh 合并路径继续保持顺序边界，旧 session 错误不覆盖当前会话上下文。

## 关键改动

- `packages/protocol/src/index.ts`：扩展 `Message.deliveryState/clientMutationId` 与 `AppError.dedupeKey/target.operation/target.text/tokens`。
- `apps/server/src/codexQueue.ts`、`apps/server/src/store.ts`：补齐 pending/sent/cancelled 队列到乐观消息的生命周期联动。
- `apps/server/src/codexSessionMerge.ts`、`apps/server/src/index.ts`、`apps/web/src/sessionMerge.ts`：provider final 与本地 optimistic outbound 按内容确认合并，不制造重复 user message。
- `apps/server/src/errors.ts`、`apps/server/src/index.ts`：统一 AppError 包装和脱敏事件入口。
- `apps/web/src/main.tsx`、`apps/web/src/styles.css`：错误卡 dedupe、429 cooldown、显式 retry target、disabled retry 状态。
